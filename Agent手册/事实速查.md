## 2 主题引擎（`src/StartUI4Controls/UI4Theme.cs`）

- `UI4ThemeMode`(:16) = `Light | Dark | System | HighContrast`。
- 静态：`Current`(:76) `CurrentMode`(:88) `ResolvedMode`(:91) `ResolvedKey`(:94) `ThemeKeys`(:172)
  `SetTheme(mode)`(:106) `Apply(key)→bool`(:149) `Register(definition)`(:161) `ApplyToApplication()`(:283)
  `FollowSystemHighContrast`(bool, 默认 **false**, :200) `ReleaseSystemFollow()`(:251)
  `Persistence`(`IThemePersistence`, 默认 null, :316) `Save()`(:324) `ApplyPersisted()→bool`(:333)
  `SetAccent(Color)`(:678) `ColorOf(token)`(:518) `BrushOf(token)`(:521)。
- 事件：`ThemeChanged`(:100, 在全部被跟踪控件刷新之后触发)、`StaticPropertyChanged`（让 XAML 能绑定
  `CurrentMode/ResolvedMode/ResolvedKey`）、`ThemeSaved`、`ThemeLoading(UI4ThemeMode)`。
- 实例：30 个 `*Color` 只读表达式属性(:526-584) + 11 个冻结画刷(:589-609)。
- **时序契约**：`NotifyThemeChanged`(:458) 先 `_themeVersion++`，再 `Dispatcher.BeginInvoke(DispatcherPriority.Input, …)`
  在一个回调里 **先 `RefreshEntries` 后 `ThemeChanged?.Invoke`**(:484)；`Application.Current == null` 时同步执行但顺序不变(:490)。
  ⇒ 宿主在 `ThemeChanged` 里读到的控件已是新主题；⇒ 想观察**命令式控件的外观 DP** 必须先泵到 `ContextIdle`（低于 `Input`）。
  注意区分：`UI4Theme.cs:186` 的资源桥重写是**同步**的，所以 `ResolvedKey` / `Current.BackgroundColor` /
  `TryFindResource("UI4.Brush.*")` 在调用返回后立刻就是新值；只有控件重刷与 `ThemeChanged` 回调走批处理。
- `IThemeAware`(:728) 是 **internal**：宿主无法为自己的控件挂命令式刷新通道（只能用 DynamicResource 通道）。
- `EffectiveThemeFor`(:666) 是 internal；`ThemeVersion`(:64) internal。
- 自定义键的 `CurrentMode/ResolvedMode` 会报告成 `Light` ⇒ 判断自定义主题要比 `ResolvedKey`。
- `UseTheme` 换入栈只允许 UI 线程同步使用(:57-61, 644-660)；刷新路径里若再用 `BeginInvoke`（低于同步换入的时机）
  会读到全局主题。注意区分两类失效：`UI4ListBox` 的序号徽章其实是**模板构建期取 `UI4Theme.Current.OnWhiteBrush` 快照**
  （`UI4ListBox.cs:403`，`NumberCircleBackground` 默认静态 `#2563EB`，`:205-210`），而该文件唯一的 `BeginInvoke`
  在按压-释放处理里（`:338-342`），不在徽章路径上。

## 4 作用域 / 自定义 / 持久化

- `UI4ThemeScope.Theme`(:24) 附加 `string`，大小写不敏感，可挂任何 `FrameworkElement`（Window、Border、UserControl）。
- 撤销语义(:63-65)：`null` / 空白 / **未注册的键** 都表示撤销作用域，回到全局；写错键名不崩。
- 两条生效通道(:13-19)：① 合并字典 → `DynamicResource`/`SetResourceReference` 消费者自动跟随；
  ② 命令式控件通过 `UseTheme` 换入栈同步重刷。嵌套以最内层为准(:155-181)。
- 作用域根若是 `Window`，标题栏一并重染（`UI4ThemeScope.cs:149-151`）。
- `UI4ThemeDefinition`(:11)：`Key` `GetColor(token)`（未设则抛 `KeyNotFoundException`）`Has` `With(token,color)`（流式）
  `Clone()`（**键会变成 `<key>.clone`**）+ 静态 `Light()`/`Dark()`/`HighContrast()`。
  自定义配方：`Clone() → With(...) → UI4Theme.Register(...) → UI4Theme.Apply(key)`。
- `SetAccent`(:678-692) 会**写回已注册的 definition**（派生 `AccentDark = 0.85×亮度`），因此它会改变后续
  `Apply("light")` 的结果——测试里要恢复或隔离（曾造成假失败）。
- `IThemePersistence`：`Save(UI4ThemeMode)` / `UI4ThemeMode? Load()`；实现 `RegistryThemePersistence`
  （写子键 `HKCU\Software\StartUI4` 下的值名 `ThemeMode`（DWORD），`UI4ThemePersistence.cs:21-22`；`Save()` 未包
  try/catch，宿主自兜；ctor 可传自定义子键）与 `JsonThemePersistence(path)`
  （手写一行 JSON `{"mode":"Dark"}`，不引第三方）。默认关闭。

## 5 标题栏（`UI4WindowTitleBar.cs`，201 行，静态类）

- 概念：DWM（Vista 起的桌面合成组件）绘制**非客户区**（标题栏/边框/圆角/投影），WPF 只画客户区；
  `WM_NCPAINT` 自绘在合成后失效，程序只能用 `DwmSetWindowAttribute`（`dwmapi.dll`）。
- 用到的属性：`20`（`USE_IMMERSIVE_DARK_MODE`，20H1 前为 `19`）、`35 CAPTION_COLOR`=`Background`、
  `36 TEXT_COLOR`=`TextForeground`、`34 BORDER_COLOR`=`BorderNormal`；撤销写哨兵 `DWMWA_COLOR_DEFAULT=0x01000000`。
  颜色为 COLORREF `0x00BBGGRR`（不是 WPF 的 `0xAARRGGBB`，alpha 丢弃）。
- 公开面：附加属性 `EnabledProperty`(bool, 默认 true) + `Get/SetEnabled`、`Apply(Window)→bool`（幂等，按
  `EffectiveThemeFor(window) ?? Current`）、`ApplyOpenWindows()`、`SupportsCaptionColors`、`ToColorRef(Color)→int`。
- 四条通路：A `ThemeChanged` 后清扫 `Application.Windows`；B 任一 UI4 控件 `Loaded` 时补染所属窗口
  （同一 `ThemeVersion` 内每窗口一次，去重表 `ConditionalWeakTable<Window, PaintedVersion>`）；
  C `UI4ThemeScope` 根为 `Window`；D 宿主手动 `Apply`（**不含任何 UI4 控件的纯窗口只能靠 D 或等下一次 A**）。
- 深浅判定：底色亮度 `0.299R+0.587G+0.114B < 128`，不枚举主题键。
- 能力探测一律「先试、按 HRESULT 定论」并缓存，**不看 `Environment.OSVersion`**（无 manifest 的进程会虚报 6.3）。
- 回读不对称（实测）：19/20 可被 `DwmGetWindowAttribute` 从外部进程回读（唯一硬证据）；34/35/36 **拒绝回读** `0x80070057`。
- 被否掉的通路：`EventManager.RegisterClassHandler(typeof(Window), LoadedEvent, …)` 在 PowerShell STA 承载下实测从不触发，不能作为产品路径。

- `UI4ColorPicker : Window`（命令式）构造 `(title=null, defaultColor=null)`；实例 `Show(Window owner=null)`
  **名字骗人、实际是模态 `ShowDialog()`**；静态 `ShowDialog(title=null, defaultColor=null, owner=null) → Color?`；
  读 `SelectedColor`。
- `UI4ContextMenu`（**普通对象，不是 Control**，代码式）`Width(160) ItemPadding BorderColor Background HoverBackground
  IsOpen`，每个外观属性带「显式赋值后主题切换不再覆盖」注记；`AddItem(UI4MenuItem)`、
  `AddItem(UI4MenuItemType, Action, Func<bool>)`、`Attach(UIElement)`、`Detach()`、`Open()`、`Close()`；
  构造时订阅 `ThemeChanged`，**`Detach()` 是唯一退订入口**（`UI4ContextMenu.cs:364-366`）——从不 `Attach`/从不 `Detach`
  的实例会永久挂在静态事件上；`SyncBeforeOpen()` 处理「未弹出过的 Popup 子元素不触发 Loaded」。
  `UI4MenuItem` POCO：`Type/Text/Icon(ImageSource)/Command(Action)/CanExecute(Func<bool>)`（**没有 `IconText`**，
  那是 `UI4TrayMenuItem` 的成员）；
  `UI4MenuItemType` = `Undo Redo Cut Copy Paste Delete SelectAll`；`UI4MenuIcons` 静态图标缓存。
- `UI4NotifyIcon : FrameworkElement, IDisposable`（P/Invoke `Shell_NotifyIcon`，非 WinForms）
  `MenuActivation(PopupActivationMode) IconSource ToolTipText MenuWidth MenuItemPadding MenuBorderColor MenuBackground
  MenuHoverBg MenuCornerRadius`，事件 `TrayLeftMouseUp/TrayRightMouseDown/TrayMouseDoubleClick`，
  `AddItem(...)`×2、`ClearMenuItems()`、`OpenMenu()`、`CloseMenu()`、`Dispose()`；`UI4TrayMenuItem` POCO。
  **生命周期**：必须在视觉树里；`Visibility` 即开关（`OverrideMetadata` 里 Visible→Create、非 Visible→Remove）；
  内部有隐藏消息 `HwndSource`、100ms `DispatcherTimer`、`Application.Exit` 订阅；
  退出必须 `Visibility=Collapsed` 然后 `Dispose()`，否则留幽灵图标；`IconSource` 经 `GetResourceStream/GetContentStream`
  解析，失败回退 `SystemIcons.Application`；宿主需自己引用 `System.Drawing`。
- `UI4CodeEditor : ICSharpCode.AvalonEdit.TextEditor` 构造里设 C# 高亮、行号、折行、Consolas 14、Tab→4 空格、
  预挂 `UI4ContextMenu`、`Loaded` 时套主题滚动条。**只要 XAML 触及该类型，`ICSharpCode.AvalonEdit.dll` 就是运行必需**。
- **internal，宿主不可用**：`UI4DataGrid`（SQLite 临时库 `%TEMP%\StartUI4_temp_*.db`，`DisposeDb()`，静态表在
  `ProcessExit` 清理）、`UI43DSphere`、`Internal/ThemeSync`（「跟随主题但尊重用户显式改动」DP 助手）、
  `Internal/ScrollBarResources`、`Internal/WindowResizeBehavior`、`Internal/WindowAnimationHelper`、`IThemeAware`、
  `Internal/ColorToBrushConverter`。
- `GeometryHelper.GetOutlinedGeometry(this RectangleGeometry)` 是公开扩展方法。

## 7 通用坑（跨章引用，勿在各章互相矛盾）

1. **MC3074 级联**：库内 C# 编译错误会让 Demo 的 XAML 报「类型不存在」。判据：先 `dotnet build` 全量看真实错误，别信 IDE 列表。
2. **本机 WPF 抓屏全白**（`PrintWindow`/`CopyFromScreen`，基线亦然）⇒ 颜色正确性只靠进程内断言 + UIA + DWM 回读；截图只是辅助。
3. **构建前先 `taskkill //IM StartUI4Demo.exe //F`**，否则 MSB3027 文件占用。
4. **泵序**：验证脚本必须先 `Dispatcher.Invoke(noop, DispatcherPriority.ContextIdle)` 再 `Render`，否则 `Input` 优先级批处理不落地。
5. **不要在被主题管理的 DP 上随手赋本地值**：一旦 `ReadLocalValue` 有值，该属性的主题跟随即失效（`Internal/ThemeSync` 语义）；
   `UI4ContextMenu` 的外观属性同理有「显式赋值后不再覆盖」注记。
6. **改 DP 触发模板重建**：命令式控件的外观 DP 变化走 `BuildXxxStyle()` 全量重建 ⇒ 动画频率级别改 DP 会掉帧；
   结构类 DP（`CornerRadius/BoxSize/InnerPadding`）重建模板，颜色类已改为引用式。
7. **Color 与 Brush 混用**：同一概念在不同控件上类型不同（`UI4Panel.BorderColor` 是 `Color`，`UI4ListView.ItemBackground` 是 `Brush`）。
8. **过时文档陷阱**（源码/注释与实现不符）：`UI4MultiLanguage` 注释说有 `SetLanguage(string)` — **不存在**；
   `UI4ComboBox` 注释列 `HoverBorderColor/FocusBorderColor` — 实际是 `FocusGradientStart/End`；
   `UI4Panel` 注释提 `Title` 属性 — 不存在；README 里残留已删除的 `UI4ContextMenuLanguage`（CS0103）。
9. **本地化是「构造期拉取」**：切语言要改 `CultureInfo.CurrentUICulture` 再 `UI4MultiLanguage.Refresh()`，
   已弹出的菜单/对话框不会重译；内置语言 zh/ja/ko/de/fr/es/ru + 默认英文，**无繁中分支**。
10. **net48 `ConditionalWeakTable`**：`TValue` 必须是引用类型、没有 `AddOrUpdate`、同键 `Add` 抛异常 ⇒ 用 `GetValue(key, factory)` + 可变盒子。
11. **UIA 定位**：库内无一处 `OnCreateAutomationPeer`，脚本必须给控件设 `x:Name`（→ `AutomationId`）或按 Name/坐标点击；
    属主窗口在 UIA 树里挂在 owner 之下（走查要用 `Descendants` + `ControlType==Window`）。
12. **C# 7.3**：见 `编写规范.md §3.3`；上游遗留 CS0414（`UI4ProgressRing`/`UI4ScrollViewer` 只写不读的字段）是预期噪声。
13. **系统跟随要显式收尾**：用过 `UI4ThemeMode.System` 的应用退出时调 `UI4Theme.ReleaseSystemFollow()`，否则 `SystemEvents` 订阅泄漏。
14. **DPI**：库不处理 DPI；`app.manifest`（PerMonitorV2）是宿主责任，Demo 已带；同一 manifest 也影响 `Environment.OSVersion` 真实性。
